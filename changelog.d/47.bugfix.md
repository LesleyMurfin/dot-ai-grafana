Query and Remediate now find a configured Alertmanager datasource, and actually read its alerts, instead of reporting the datasource missing (or silently showing none) on every install. Two separate defects combined to hide Alertmanager evidence entirely: (1) the lookup asked Grafana's datasource registry for datasources of type `alertmanager` without also asking for datasources that declare no metrics/logs/tracing/annotations/alerting capability — exactly how Grafana's built-in Alertmanager datasource describes itself, so it was silently excluded from every result; and (2) even once found, Grafana's built-in `AlertManagerDatasource.query()` is a permanent stub that always returns no data, so the existing query-based read path could never return real alerts. The lookup now passes `all: true` to include the datasource, and alert evidence is now read via a direct call to the datasource's own `/api/v2/alerts` route (the same mechanism Grafana's own Alertmanager datasource uses internally), scoped to the question's pod/namespace when present. If that call fails or is forbidden, Current reports the failure explicitly rather than implying there are no alerts.
